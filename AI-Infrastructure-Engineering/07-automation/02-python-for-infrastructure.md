# Python for Infrastructure

> **The one-sentence model:** Python is for the parts Bash handles badly — structured data, HTTP APIs, retries, concurrency, and testable logic. A good infrastructure tool has explicit inputs, typed data, timeouts, bounded retries, structured logs, and no secrets in exceptions.

---

## 1. When to use Python

Use Python when you need:

- JSON/YAML/API parsing with real data structures;
- HTTP clients with pagination, auth, retries, and timeouts;
- concurrency across many hosts/API calls;
- reusable logic with unit tests;
- cross-platform behavior (macOS/Linux/Windows).

Keep Bash for a short sequence of commands; use Ansible for convergent host configuration; use Python for orchestration and custom integrations that neither handles cleanly.

## 3. CLI contract

Use `argparse`, return an `int` exit code, and keep `main()` testable:

```python
def main(argv: list[str] | None = None) -> int:
    parser = argparse.ArgumentParser(prog="capacity-report")
    parser.add_argument("--servers", type=Path, required=True)
    parser.add_argument("--flavors", type=Path, required=True)
    parser.add_argument("--format", choices=("table", "json"), default="table")
    parser.add_argument("-v", "--verbose", action="store_true")
    args = parser.parse_args(argv)

    logging.basicConfig(
        level=logging.DEBUG if args.verbose else logging.INFO,
        format="%(asctime)s %(levelname)s %(name)s %(message)s",
        stream=sys.stderr,
    )
    try:
        report = build_report(args.servers, args.flavors)
    except (OSError, ValueError, json.JSONDecodeError) as exc:
        logging.error("%s", exc)
        return 1
    print(render(report, args.format))
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

Exit codes: `0` success, `1` runtime/data error, `2` usage error (argparse uses 2). Logs go to stderr; the report goes to stdout.

## 4. HTTP clients

### Timeouts are mandatory

```python
import requests

session = requests.Session()
response = session.get(
    url,
    headers={"Authorization": f"Bearer {token}"},
    timeout=(3.05, 10),  # connect, read
)
response.raise_for_status()
data = response.json()
```

Without a timeout, a stuck server can hang your job forever. The connect timeout should be short; the read timeout depends on the API.

### Retries, carefully

Retry only when the operation is safe to repeat:

- `GET`, `HEAD`, `PUT` (idempotent by contract), and `DELETE` are usually safe.
- `POST` is not automatically safe. Use an idempotency key if the API supports one, or do not retry.
- Retry `429`, `408`, `502`, `503`, `504`, connection errors, and timeouts; do not retry `400`, `401`, `403`, `404` (fix the request/auth).
- Use exponential backoff with jitter, a maximum attempt count, and an overall deadline.

```python
import random
import time

def get_with_retry(session: requests.Session, url: str, *, attempts: int = 4) -> dict:
    last_exc: Exception | None = None
    for attempt in range(1, attempts + 1):
        try:
            r = session.get(url, timeout=(3.05, 10))
            if r.status_code in {429, 408, 502, 503, 504}:
                raise requests.HTTPError(f"retryable status {r.status_code}", response=r)
            r.raise_for_status()
            return r.json()
        except (requests.Timeout, requests.ConnectionError, requests.HTTPError) as exc:
            last_exc = exc
            if attempt == attempts:
                break
            delay = min(2 ** (attempt - 1) + random.random(), 10)
            time.sleep(delay)
    raise RuntimeError(f"GET {url} failed after {attempts} attempts") from last_exc
```

Respect `Retry-After` for 429/503 when present. A retry storm can turn a partial outage into a full one; bound concurrency and add jitter.

### Pagination

Never assume the first page is the full list. Follow the API's cursor/marker/next link, cap the page count, and detect loops:

```python
def iter_servers(session: requests.Session, base_url: str) -> Iterator[dict]:
    url: str | None = f"{base_url}/servers?limit=100"
    seen: set[str] = set()
    while url:
        if url in seen:
            raise RuntimeError(f"pagination loop at {url}")
        seen.add(url)
        payload = get_with_retry(session, url)
        yield from payload.get("servers", [])
        url = payload.get("next")
```

### TLS and auth

- Keep certificate verification on. Never set `verify=False` to "fix" a TLS error; fix the CA/trust store.
- Do not log `Authorization`, cookies, or tokens. A `requests` exception can include the URL but not headers; still redact.
- Prefer short-lived tokens/OIDC over static keys. Store secrets in a secret manager or environment, not in code.
- For OpenStack, application credentials are scoped and expiring; for AWS, use roles/IRSA/OIDC.

## 5. Subprocess without footguns

Use a list of arguments, `check=False` plus explicit handling, a timeout, and no shell:

```python
import subprocess

def openstack_json(args: list[str], *, timeout: float = 30) -> object:
    cmd = ["openstack", *args, "-f", "json"]
    try:
        result = subprocess.run(
            cmd,
            check=False,
            capture_output=True,
            text=True,
            timeout=timeout,
        )
    except FileNotFoundError as exc:
        raise RuntimeError("openstack CLI not found") from exc
    except subprocess.TimeoutExpired as exc:
        raise RuntimeError(f"command timed out: {' '.join(cmd)}") from exc

    if result.returncode != 0:
        raise RuntimeError(
            f"command failed ({result.returncode}): {' '.join(cmd)}\n{result.stderr.strip()}"
        )
    try:
        return json.loads(result.stdout)
    except json.JSONDecodeError as exc:
        raise RuntimeError(f"invalid JSON from {' '.join(cmd)}") from exc
```

- **Never** use `shell=True` with a string built from user input; it enables command injection. If you need a shell pipeline, write it explicitly and validate every variable.
- `check=True` raises `CalledProcessError`; catch it if you want a custom message. `check=False` plus a status check is often clearer.
- `capture_output=True` uses pipes; for very large output, stream to a file instead of buffering.
- `timeout` kills the child but not necessarily its grandchildren; use process groups for complex commands.
- Pass `env=` explicitly when the child must not inherit secrets; inherit `PATH` deliberately.
- Use `cwd=` and absolute paths; do not rely on the caller's working directory.

For SSH, prefer a library (Paramiko/fabric) or an Ansible module; if you shell out, use `BatchMode=yes`, a known_hosts file, and a timeout.

## 6. Data modeling and validation

Use `dataclasses` or `TypedDict` for internal structure, and validate at the boundary:

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Flavor:
    name: str
    vcpus: int
    ram_mb: int
    disk_gb: int

@dataclass(frozen=True)
class Server:
    name: str
    project: str
    flavor: str
    status: str
```

```python
def parse_flavor(raw: dict) -> Flavor:
    try:
        return Flavor(
            name=str(raw["Name"]),
            vcpus=int(raw["VCPUs"]),
            ram_mb=int(raw["RAM"]),
            disk_gb=int(raw["Disk"]),
        )
    except (KeyError, TypeError, ValueError) as exc:
        raise ValueError(f"invalid flavor record: {raw!r}") from exc
```

- Validate required keys, types, and ranges; fail with the record/ID, not a bare `KeyError`.
- Treat API fields as untrusted; a missing field is a data error, not an invitation to `dict.get(..., 0)` silently.
- Use `pydantic` if you need rich schema validation; stdlib is fine for small tools.
- Normalize units explicitly (`MB` vs `MiB`, `GB` vs `GiB`). A 1024 vs 1000 bug can hide for months.

## 7. Concurrency

For I/O-bound work (HTTP, SSH, DNS), use `ThreadPoolExecutor` with a bounded worker count:

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

def fetch_all(urls: list[str], *, workers: int = 8) -> dict[str, dict]:
    results: dict[str, dict] = {}
    with ThreadPoolExecutor(max_workers=workers) as pool:
        futures = {pool.submit(get_with_retry, session, url): url for url in urls}
        for future in as_completed(futures):
            url = futures[future]
            try:
                results[url] = future.result()
            except Exception as exc:  # log per-item, do not lose the batch
                logging.error("fetch failed for %s: %s", url, exc)
    return results
```

- Bound the pool; unbounded threads exhaust sockets/memory and hammer the API.
- Handle each future's exception; one failure should not silently discard the batch.
- For CPU-bound work, use `ProcessPoolExecutor`; threads do not bypass the GIL for pure Python CPU work.
- For rate-limited APIs, use a semaphore/token bucket; `ThreadPoolExecutor` alone does not rate-limit.
- Prefer `asyncio` only if the team already uses it; it adds a different debugging model.

## 8. Secrets and logging

- Read secrets from a secret manager or environment; never hard-code them.
- Do not print `os.environ`, request headers, or full exception locals. Redact tokens/keys.
- Use `logging`, not `print`, for diagnostics; include request IDs and resource IDs.
- Set file permissions on any credential file (`0600`) and never commit `.env`.
- Scan dependencies (`pip-audit`) and avoid `pickle`/unsafe YAML from untrusted sources.
- If a secret is exposed, rotate it; deleting the log line is not enough.

```python
def redact(value: str) -> str:
    if len(value) <= 8:
        return "***"
    return f"{value[:4]}...{value[-4:]}"
```

## 9. Testing

### Unit tests

Test pure functions with fixtures; do not require a cloud:

```python
# tests/test_report.py
import json
from pathlib import Path

import pytest

from capacity_report.report import build_report

FIXTURES = Path(__file__).parent / "fixtures"

def test_groups_by_project() -> None:
    report = build_report(FIXTURES / "servers.json", FIXTURES / "flavors.json")
    demo = next(p for p in report.projects if p.project == "demo")
    assert demo.servers == 2
    assert demo.vcpus == 6

def test_unknown_flavor_fails() -> None:
    with pytest.raises(ValueError, match="unknown flavor"):
        build_report(FIXTURES / "servers-unknown.json", FIXTURES / "flavors.json")
```

```bash
pytest -q
pytest --cov=capacity_report --cov-report=term-missing
```

### HTTP tests

Use `responses` or `respx` to simulate status codes, timeouts, pagination, and retries. Do not hit a real cloud in unit tests; use a sandbox for integration tests.

### Subprocess tests

Inject a fake executable via `PATH` or refactor the command construction into a pure function and assert the argv list. Test timeouts and non-zero exit paths.

### Integration tests

Run against a disposable project/VM, tagged and cleaned up. Keep them few, slow, and opt-in (`pytest -m integration`). A green unit suite does not prove the API contract or IAM policy.

## 10. A complete example: `capacity-report`

This tool reads `openstack server list --long -f json` and `openstack flavor list -f json`, joins them, and reports per-project requested vCPU/RAM/disk. It does not call OpenStack itself, so it is easy to test.

`src/capacity_report/models.py`:

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Flavor:
    name: str
    vcpus: int
    ram_mb: int
    disk_gb: int

@dataclass(frozen=True)
class Server:
    name: str
    project: str
    flavor: str
    status: str

@dataclass
class ProjectUsage:
    project: str
    servers: int = 0
    vcpus: int = 0
    ram_mb: int = 0
    disk_gb: int = 0

@dataclass
class Report:
    projects: list[ProjectUsage]
    total: ProjectUsage
```

`src/capacity_report/report.py`:

```python
import json
from pathlib import Path

from .models import Flavor, ProjectUsage, Report, Server


def _load(path: Path) -> list[dict]:
    with path.open(encoding="utf-8") as fh:
        data = json.load(fh)
    if not isinstance(data, list):
        raise ValueError(f"{path}: expected a JSON array")
    return data


def parse_flavors(path: Path) -> dict[str, Flavor]:
    flavors: dict[str, Flavor] = {}
    for raw in _load(path):
        try:
            flavor = Flavor(
                name=str(raw["Name"]),
                vcpus=int(raw["VCPUs"]),
                ram_mb=int(raw["RAM"]),
                disk_gb=int(raw["Disk"]),
            )
        except (KeyError, TypeError, ValueError) as exc:
            raise ValueError(f"invalid flavor record: {raw!r}") from exc
        flavors[flavor.name] = flavor
    return flavors


def parse_servers(path: Path) -> list[Server]:
    servers: list[Server] = []
    for raw in _load(path):
        try:
            servers.append(
                Server(
                    name=str(raw["Name"]),
                    project=str(raw.get("Project") or "unknown"),
                    flavor=str(raw["Flavor"]),
                    status=str(raw["Status"]),
                )
            )
        except (KeyError, TypeError, ValueError) as exc:
            raise ValueError(f"invalid server record: {raw!r}") from exc
    return servers


def build_report(servers_path: Path, flavors_path: Path) -> Report:
    flavors = parse_flavors(flavors_path)
    by_project: dict[str, ProjectUsage] = {}
    total = ProjectUsage(project="TOTAL")

    for server in parse_servers(servers_path):
        if server.status == "DELETED":
            continue
        try:
            flavor = flavors[server.flavor]
        except KeyError as exc:
            raise ValueError(f"unknown flavor {server.flavor!r} for server {server.name!r}") from exc

        usage = by_project.setdefault(server.project, ProjectUsage(project=server.project))
        for item in (usage, total):
            item.servers += 1
            item.vcpus += flavor.vcpus
            item.ram_mb += flavor.ram_mb
            item.disk_gb += flavor.disk_gb

    return Report(projects=sorted(by_project.values(), key=lambda p: p.project), total=total)


def render(report: Report, fmt: str) -> str:
    if fmt == "json":
        return json.dumps(
            {
                "projects": [vars(p) for p in report.projects],
                "total": vars(report.total),
            },
            indent=2,
        )
    rows = [("PROJECT", "SERVERS", "VCPU", "RAM_MB", "DISK_GB")]
    rows += [(p.project, str(p.servers), str(p.vcpus), str(p.ram_mb), str(p.disk_gb)) for p in report.projects]
    rows.append((report.total.project, str(report.total.servers), str(report.total.vcpus),
                 str(report.total.ram_mb), str(report.total.disk_gb)))
    widths = [max(len(row[i]) for row in rows) for i in range(len(rows[0]))]
    return "\n".join("  ".join(cell.ljust(widths[i]) for i, cell in enumerate(row)) for row in rows)
```

`src/capacity_report/cli.py`:

```python
import argparse
import json
import logging
import sys
from pathlib import Path

from .report import build_report, render


def main(argv: list[str] | None = None) -> int:
    parser = argparse.ArgumentParser(prog="capacity-report")
    parser.add_argument("--servers", type=Path, required=True,
                        help="output of: openstack server list --long -f json")
    parser.add_argument("--flavors", type=Path, required=True,
                        help="output of: openstack flavor list -f json")
    parser.add_argument("--format", choices=("table", "json"), default="table")
    parser.add_argument("-v", "--verbose", action="store_true")
    args = parser.parse_args(argv)

    logging.basicConfig(
        level=logging.DEBUG if args.verbose else logging.WARNING,
        format="%(levelname)s %(message)s",
        stream=sys.stderr,
    )
    try:
        report = build_report(args.servers, args.flavors)
    except (OSError, ValueError, json.JSONDecodeError) as exc:
        logging.error("%s", exc)
        return 1
    print(render(report, args.format))
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```


### `python3 -m venv`

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -U pip
```

**Why:** isolate dependencies. Never `pip install` into the system Python on a shared host.

### `pytest`

```bash

```

**Interpretation:** failures show the input/assert; coverage shows unexercised branches, not correctness.

### `ruff`

```bash
ruff check .
ruff format --check .
```

**Why:** fast lint/format; catches unused imports, undefined names, style drift. Configure in `pyproject.toml`.

### `mypy`

```bash
mypy src
```

**Why:** catches type mismatches before runtime, especially around `None` and dict values. Strict mode is a goal, not a first-day requirement.

### `python -m json.tool`

```bash
python -m json.tool response.json >/dev/null
```

**Why:** quick JSON validation without `jq`. For queries, use `jq`.

### `strace` / `py-spy` (debugging)

```bash
strace -f -p <pid> -e trace=network,openat
py-spy dump --pid <pid>
```

**Why:** see syscalls/stack when a process hangs. `strace` is Linux-only and can slow the process; use briefly. `py-spy` needs permission to inspect the process.

### `timeout`

```bash
timeout 30s python tool.py
```

**Why:** bound a job in CI/cron. The tool should also have internal timeouts; the outer timeout is a backstop.

## 12. Failure scenarios

### A — Request hangs forever

No timeout on the HTTP call. Add connect/read timeouts and an overall deadline; test with a fake server that never responds.

### B — Retry storm

All clients retry immediately on 503, amplifying load. Use exponential backoff + jitter, cap attempts, honor `Retry-After`, and retry only safe operations.

### C — `KeyError` on an API field

Assume the schema changed or the endpoint returned an error object. Validate the response, log the resource ID and status, and fail with a clear message. Do not use `.get(..., 0)` for required capacity fields; zero hides the bug.

### D — Subprocess deadlock

Using `Popen` with both stdout/stderr pipes and calling `wait()` before reading can deadlock when the pipe buffer fills. Use `communicate(timeout=...)` or stream to files.

### E — Secret in an exception

A URL with a token query parameter or a request header is logged. Redact before logging, use headers not query strings for secrets, and rotate if exposed.

### F — Partial failure hidden

A loop catches every exception and continues, then exits 0. Track failures, report them, and return non-zero if any required item failed. Define partial-failure semantics explicitly.

### G — Thread race on shared state

Multiple threads mutate a dict/list without a lock. Use per-thread results and merge in the main thread, or protect shared state. Prefer immutable data.

### H — Works locally, fails in CI

Different Python version, missing env var, no TTY, different locale/timezone, missing system dependency, or network egress blocked. Pin the version, log the environment (redacted), and run the same container/venv in CI.

### Answers

1. A stuck peer/DNS/LB can hang the process indefinitely; timeouts bound the failure and let retries/alerting work.
2. `GET`/`HEAD`/`PUT`/`DELETE` are idempotent by contract; `POST` can create duplicates, so retry only with an idempotency key or not at all.
3. Wait exponentially longer per attempt plus random jitter; jitter prevents synchronized retries (thundering herd).
4. They are auth/policy errors; retrying the same request will fail until credentials/permissions change.
5. It raises `HTTPError` for 4xx/5xx, so the caller does not accidentally parse an error body as success.
6. It invokes a shell, so untrusted input can inject commands/redirects; use an argv list.
7. `check=True` raises `CalledProcessError` automatically; manual checking lets you craft a specific error/exit code and inspect stderr.
8. The child can block writing to a full pipe while the parent waits; `communicate()` drains both pipes.
9. Threads share memory and suit I/O-bound work; processes have separate memory and suit CPU-bound Python work (GIL).
10. It can exhaust sockets/memory and overwhelm the API; bound workers and rate-limit.
11. Data/report to stdout; logs/diagnostics to stderr, so redirection captures clean data.
12. A missing field becomes zero, silently under-reporting capacity; fail loudly or validate the schema.
13. It proves your logic against the fixtures; it does not prove the real API/OS/IAM behaves that way.
14. They are slower, need credentials/resources, and can be flaky; keep them few, tagged, and run on demand/merges.
15. Never log headers/URLs containing secrets; redact, use headers instead of query params, and rotate if exposed.
16. Recording exact dependency versions so installs are reproducible; unpinned transitive updates can break automation.
17. It disables certificate verification, enabling MITM; fix the CA/trust store instead.
18. A client-supplied unique key that lets the server recognize a repeated create; needed when retrying non-idempotent `POST`.
19. Collect per-item results/errors, continue where safe, report failures, and return non-zero if required items failed.
20. Python version, env vars, working directory/PATH, user/permissions, TTY, network egress, and installed dependencies; reproduce with the same non-interactive environment.
