## Cluster 1: Virtual Users, Scripting Model, Thresholds

### What is it?
k6 load tests are written as JavaScript scripts defining what a **virtual user (VU)** does per iteration; you configure how many VUs run concurrently and for how long (or ramp up/down over stages). **Thresholds** turn a load test into a pass/fail check (e.g., "fail the test if p95 latency exceeds 200ms"), rather than just producing a report a human has to manually interpret.

### How does it work?
```js
import http from 'k6/http';
export const options = {
  stages: [{ duration: '30s', target: 100 }, { duration: '1m', target: 100 }],
  thresholds: { http_req_duration: ['p(95)<200'] },   // test FAILS if this isn't met
};
export default function () {
  http.get('https://api.example.com/tasks');
}
```

- **L1:** "k6 scripts define virtual-user behavior in JavaScript, ramps VUs up over configurable stages, and can enforce thresholds that fail the test automatically if a metric like p95 latency crosses a defined bound."
